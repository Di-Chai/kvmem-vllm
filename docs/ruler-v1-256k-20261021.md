## Implemented preparation checks

`scripts/prepare_ruler_corpora.py` downloads the 218 upstream-listed essays,
SQuAD, HotpotQA, the Git-LFS-backed English vocabulary (verified against its
official object hash), and NLTK sentence data. Transport uses HTTPS and raw
GitHub URLs. The task generators and scoring code are not modified.

The 256K setting is the upstream generation length budget, not a claim that
every rendered input has exactly 262,144 tokens. FWE's official coarse word
increments produced inputs near 247K–261K tokens; other tasks are generally
closer to the upper limit. The final `dataset-summary.json` gives measured
per-task minima, maxima, and means. Inputs are neither padded nor truncated.

`scripts/benchmark_ruler.py` invokes the official generators with argument
arrays, keeps complete input text, verifies actual length, and checks public
Query boundaries after chat wrapping. It assigns file ordinals as case IDs
because the upstream NIAH generator overwrites its `index` with an answer
character position; the upstream index is retained as metadata.

`scripts/ruler_protocol.py` validates all 13 task counts, unique case identities,
reference answers, and public Query extraction. Query extraction reads only the
public task text. It loads the official scoring functions and normalizer after
checking their frozen source hashes.

For a thinking model, only text after the thinking terminator is scored. An
unfinished thinking segment yields an empty answer. This answer extraction must
be reported as part of the model protocol. The metric itself remains the official
case-insensitive substring coverage (or any-alias match for QA). Supplementary
full-reference recall is explicitly not exact-answer accuracy. Task scores are
computed in batches using upstream rounding, then averaged equally across tasks.

Validation completed:

- Integration with the byte-verified official scorer passed for all 13 tasks,
