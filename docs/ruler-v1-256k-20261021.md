## Scope

- Classic RULER v1: all 13 tasks, at a target context length of 262,144 tokens.
- Official repository: <https://github.com/NVIDIA/RULER>.
- Frozen source commit: `c3f5e3b4f87f97e048793bb510a3a6b19a46bf3a`.
- Source snapshot: `artifacts/ruler-v1-256k-20261021-r1/upstream/` (data disk).
- The original paper uses 500 examples **per task and per context length**;
  one length therefore has 6,500 examples. Its main length sweep was 4K–128K.
  Source: <https://arxiv.org/html/2404.06654v3#S4>.
- Official code default: `scripts/config_tasks.sh`, `NUM_SAMPLES=500`.
- Covering all tasks with 20 examples each would have 260 examples. It must be

## Intended model configuration

Reuse the frozen runtime and NIAH profile from
`artifacts/fused-stable-quality-20261021-r1`: repaired four optimizations on,
guided off, cumulative-attention pressure selection, V2 multi-graph Query
selection with alpha 0.2, K=36,864, G=16,384, NVFP4, FP8 KV, compiled MTP4.
The user subsequently authorized pausing MAB to prioritize RULER. MAB was
paused with 526 of 1,116 cases completed and no errors among those completed
cases. Five interrupted attempts were archived separately; 590 cases remain.
Completed result hashes and recovery details are in the MAB campaign's
`pause-state.json`. RULER restores the recorded DSH service when it exits;
MAB remains paused.

Generation uses the same sampling settings as the C-semantic NIAH campaign:
temperature 1, top-p .95, top-k 20, maximum 8,192 output tokens, and a 4,096-token
thinking budget. The KV generation allowance remains 16,384. Each example uses
a fresh independent owner, with at most eight requests admitted concurrently.
The official task input is wrapped as a Qwen user message and opens thinking;
the optional assistant answer prefix is omitted. Exact settings, input hashes,
public Query coordinates, and actual lengths are frozen before inference.
Matching the official sample count alone does not make a 256K compressed-KV
run directly comparable to an older full-context 128K result.

## Implemented preparation checks

`scripts/prepare_ruler_corpora.py` downloads the 218 upstream-listed essays,
SQuAD, HotpotQA, the Git-LFS-backed English vocabulary (verified against its
official object hash), and NLTK sentence data. Transport uses HTTPS and raw
GitHub URLs. The task generators and scoring code are not modified.

The 256K setting is the upstream generation length budget, not a claim that
every rendered input has exactly 262,144 tokens. FWE's official coarse word
increments produced inputs near 247K–261K tokens; other tasks are generally
closer to the upper limit. The final `dataset-summary.json` gives measured
per-task minima, maxima, and means. Inputs are neither padded nor truncated.

`scripts/benchmark_ruler.py` invokes the official generators with argument
arrays, keeps complete input text, verifies actual length, and checks public
Query boundaries after chat wrapping. It assigns file ordinals as case IDs
because the upstream NIAH generator overwrites its `index` with an answer
character position; the upstream index is retained as metadata.

`scripts/ruler_protocol.py` validates all 13 task counts, unique case identities,
reference answers, and public Query extraction. Query extraction reads only the
public task text. It loads the official scoring functions and normalizer after
checking their frozen source hashes.

For a thinking model, only text after the thinking terminator is scored. An
unfinished thinking segment yields an empty answer. This answer extraction must
be reported as part of the model protocol. The metric itself remains the official
case-insensitive substring coverage (or any-alias match for QA). Supplementary
full-reference recall is explicitly not exact-answer accuracy. Task scores are
computed in batches using upstream rounding, then averaged equally across tasks.

These are adapter checks, not model accuracy results. Consult `status.json`,
`run/answers/progress.json`, and eventually `run/answers/scores.json` in the
artifact directory for inference status and accuracy. Partial results must not
be presented as a complete-suite macro score.

The first attempt exposed a result-summary bug: pressure reports do not carry
the Query-only `added_blocks` field. Summarization now reads that field only
from Query reports, while retaining the pressure, accepted-attention and owner
release audits. Five saved responses passed offline revalidation with the
frozen official scorer. The interrupted attempts remain separate from completed
suite results; they do not establish a 13-task macro score.

The G64K diagnostic explicitly changes only the KV generation budget in the
model profile. Output remains capped at 8,192 tokens, with 4,096 thinking tokens.
The default suite validator still requires G16K; overriding G requires an
explicit diagnostic cohort and budget argument. See
`docs/pressure-prefill-profile-20261021.md` for performance scope and limitations.
