# FPS-4 缓存发布优化

本轮只优化 `query_fps_optimized=true` 内部的冷缓存发布，不改变 FPS-4 代表选择、近平分 CPU 回退、Query 评分、成组选页、固定保留或 KV 预算。`query_fps_optimized=false` 保留原严格路径；全局默认未改。

## 改动

1. 有限 FP8 e4m3fn 代表 Key 在 GPU 无损转换到缓存 FP16/BF16/FP32，再复制到 CPU。省去整批 CPU dtype 转换和两次 FP32 展开比较。所有有效原始 K 的有限性检查保留；CPU、非 FP8 路径仍逐批执行原严格转换检查。
2. 连续 dirty blocks 直接按缓存切片批量复制；稀疏更新仍使用原 index-copy，未改变缓存布局或 owner/budget 管理。
3. 发布前使整批 signature 失效，只有 Key 与 offset 两次写入都成功才发布签名。故障重试只重建无效记录；之前已完成的批次可复用。
4. 新 GPU 转换缓冲计入 512 MiB 临时空间上限；新增实际执行分支计数。

设备转换算入 FPS 构建阶段，因此新旧 `fps_select_seconds`/`fps_publish_seconds` 的分界稍有调整。以下以完整冷构建与总区间判断收益，避免将前移的成本当作消除。

## 固定 Q/K 交错组件对照

来源为先前真实 256K 0011 诊断捕获的 16 层 FP8 K/Q，8,186 个原始 block。旧模块与其基类从上一轮冻结 runtime 加载；候选使用本轮源码。顺序 old/new、new/old、old/new，各三次，每轮清空派生缓存。

两侧运行真正的 `RawKeyFPSCache.snapshot` 与评分 API；读取使用相同的 owned mmap Key slab 适配器。文件哈希预热 OS 页缓存，所以“冷”明确指派生 FPS 缓存，不指磁盘页缓存，也不是模型 prefill 吞吐。

| 中位数 | 上一轮优化版 | 本轮发布优化 |
|---|---:|---:|
| 完整冷构建 | 8.794 s | 2.600 s |
| 评分 | 0.084 s | 0.082 s |
| 完整冷构建＋评分 | 8.878 s | 2.682 s |
| 发布子区间 | 6.680 s | 0.533 s |

完整区间耗时减少 **69.79%**，约 **3.31 倍**速度。三次候选完整区间分别为 2.679、2.682、2.684 s。

每次均与原 CPU 参考核验全部 2,095,616 个 offset、所选原始 Key 对应的缓存字节；新旧所有页分数逐位一致，原生 picker 一致。每次均有 9,647/523,904 组触发同一个近平分 CPU 守卫，未通过放宽回退减少计算。每个 owner 的缓存仍为 1.018 GiB，测试 GPU allocated 峰值均为约 355 MiB。CPU RSS 为近似采样且受 allocator 保留影响，不据此声称 CPU 内存下降。

证据：`artifacts/query-fps-publication-component-20261023-r2/summary.json`，含每轮结果、环境、源码快照、哈希和清理证明。脚本为 `scripts/benchmark_query_fps_publication.py`。

首轮 r1 在旧路径测量后、为一维页分数计算摘要时遇到标量字节视图错误；已保留失败记录，修复 benchmark 后新建 r2 重新执行全部三对。没有按性能数值选择重试，也未覆盖旧答案/计时。

## 正确性与真实服务检查

GPU/CPU 定向测试验证全部有限 FP8 位模式（含 subnormal、正负零）到三种缓存 dtype 的逐字节往返；还覆盖 GQA 评分、近平分、部分页、连续/稀疏更新、跨批次部分写失败、共享预算及热缓存。启用 GPU 的定向测试集 61 项通过，既有性能组件和配置/组选择回归亦通过。benchmark 的标量分数摘要已增加回归测试，其测试集 4 项通过。

真实服务仅预先固定原样本 0008、0009 两题；完整原 12 题 fixture 保持不变，measurement-plan 明确本轮仅为两题集成/性能检查。NVFP4、FP8 KV、MTP4、K=36,864、G=16,384、sink=1,312、recent=0、chunk=2,048、输入/种子/采样均与上一轮相同，继续 FPS-4＋预算内左右一块成组选页、alpha=0。旧结果只读，不按答案重试。

真实服务证据入口：`artifacts/query-fps-publication-live-20261023-r1`。此两题不替代上一轮 12/12 质量结果，也不构成新的完整 RULER 质量评测。

两题均已完成并通过最终执行/输入/原生 picker 审计，旧答案及其哈希保持不变，GPU 和服务进程已释放。两题种子分数、最终选页与上一轮逐位/逐项一致，均完整召回并答对。
