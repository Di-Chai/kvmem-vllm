# Settings

Every `KVMEM_*` setting the package reads goes through `vllm_kvmem.settings`
(`get`, `require`); a test forbids reading them from `os.environ` anywhere else. Part of
step 6 of the [layering plan](layering.md).

## Where a value comes from

Later sources win:

1. **The preset.** `default-on` (the default) is the table in `defaults.py`: flags measured
   to be effective and exact, plus the rolling-decode scoring policy. `legacy` sets none.
2. **The profile.** A serving profile may carry a `settings` object with two namespaces:

   ```json
   "settings": {"preset": "default-on",
                "system":   {"KVMEM_GIL_GATE_MS": "50"},
                "strategy": {"KVMEM_LAYERWISE_DECODE_SCOPE": "all"}}
   ```

   `system` holds settings that never change model output, `strategy` the ones that may.
   The launcher refuses an unknown name, a name filed in the wrong namespace, and a name it
   derives itself from the profile options and launch flags.
3. **Explicit environment values** given to one launch (the execution flags of an A/B arm),
   which override the profile.

`python -m vllm_kvmem.settings effective RUN/server/launch.json` lists a launch's effective
settings with their source (`launch` or `preset`) and namespace.

## Namespaces

- **system:** the default-on table (all measured exact, apart from the rolling-decode
  scoring flags) and diagnostics (traces, profiles, timing, verification).
- **strategy:** settings known to change which blocks are kept, retrieved or retained.
- **launcher:** derived from the profile options and the `--layerwise-*` flags; not settable.
- **unverified:** no recorded run shows the setting exact. A profile must file it under
  `strategy` until one does.
