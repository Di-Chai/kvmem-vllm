# Verified artifact GC experiment

This opt-in DSH experiment supplies real semantic evidence to the existing native history worker. It reclaims only complete blocks strictly inside a model-generated `write` file body. The literal accepted-token bytes must match the parsed file content, the exact successful DSH tool result must reference that call, and the actual workspace file must match byte for byte. Source spans exclude paths, tool framing, surrounding reasoning, mixed blocks, and partial tails. Sealed tool-result blocks remain protected as witnesses.

This is **artifact-backed semantic eligibility**, not an attention-coldness estimator, R-KV, or a concurrent model judge. One successful file equality check is one observation; importance stays at 1 (no low-importance claim), cold remains false. The explicit experiment profile sets `min_observations=1`, `min_cold_observations=0`, `max_importance=1`. Zero cold observations disables that gate only when explicitly configured. Defaults stay 3 observations / 3 cold observations / importance <= 0.1. Completion without a genuine observation, mandatory blocks, selection holds, stale revisions, and stale generations remain rejected.

The owning bridge prepares evidence only at tool boundaries and verifies exact accepted prefix reuse. A loopback development RPC arms a bounded worker plan, which checks the actual worker session namespace, generation and full prompt-token SHA256 before registering archive handles. The normal authority polling boundary flushes bounded evidence; all irreversible retirement and CPU payload release still use the native worker. Ordinary serving loads neither the development RPC nor this producer.

Start the server with `python -m diagnostics.dsh_artifact_gc --config PROFILE --run-dir NEW_RUN`. The profile must use loopback and the explicit parameters above. Start DSH bridge with `--artifact-gc-root WORKSPACE`, C1 admission, the pinned system frame, and backend `http://127.0.0.1:8186`. Snapshots are saved with each committed response, and each candidate has exact source/result positions and a file hash. No extra model request runs for GC.

Acceptance requires nonzero candidate-specific native retirement and CPU completion **before owner cleanup**, later accepted decode tokens, subsequent real model/tool requests, and independent browser checks on model-produced files. GPU working-window membership must be reported separately: a freed CPU source may temporarily remain in the current GPU window, and checkpoint rewind can replay accepted text and recreate KV. A successful short task does not establish long-context quality, statistical threshold calibration, or zero throughput impact. The retained file is the operational artifact; automatic recovery of historical file versions from an immutable content store is not implemented by this experiment.

## Query/checkpoint handoff

The experiment resolves each restored authority through the current runtime request binding; its archive request ID is stable across requests and cannot be used as the active binding key. Evidence supports separate write calls in the same model response and exact successful Created/Updated file results. Older committed writes may supply evidence only while their file bytes still match and their actual generated IDs remain an exact slice of the current prompt.

P/M checkpoint holds remain intact during decode. At the next public Query selection, an opt-in callback can exclude verified source blocks from an otherwise all-fit history. It retains every other record and checks the native picker preview for exact membership before ordinary fenced assembly. The configured K remains 36,864; the selected window is smaller because source records are deliberately excluded. Pressure selection and histories beyond K use the original path. The old checkpoint is removed only by normal checkpoint replacement, after which the native worker can retire the sources. No P/M protection is forcibly dropped. Evidence reset on a validated rewind requires registration against the new live generations.

A tool-result witness may include surrounding mixed framing to protect at least one sealed full block intersecting the real result; such extra protection cannot overlap a reclaimed source block.

The normal scheduler deliberately skips Query selection below K. For proactive GC the bridge therefore uses an explicit `force` at a new, provenance-verified user Query when it has armed artifact candidates. Forced Query boundaries now participate in both refresh reservation and launch below K; auto behavior and configured K/G remain unchanged. Stable tool callbacks and output continuation segments keep auto mode. This adds one boundary refresh, not a concurrent judge request or a periodic decode interruption.
