# KVMem–vLLM 开发与验收汇总（2026-09-29）

当前是**可运行的实验性集成，尚未完成长期多会话、高吞吐和任务质量验收**。
代码在独立仓库开发；原 qw3 仓库仅用作语义、模型与测试输入参考。
本文是本次 GitHub 提交的状态快照。旧开发日志中的“待测试”描述可能已过时，
请以本页所列证据及限制为准。机器可读检查汇总见
[evidence/20260929-summary.json](evidence/20260929-summary.json)。

## 配置与支持边界

- 已测主线：Qwen3.8-27B GGUF **Q8_0 目标权重、FP8 e4m3 目标 KV**，
  DFlash2 BF16 草稿及其原生 BF16 sliding KV；每请求 **K131072/G65536**，权威记录 B128。
- 实际模型结构为 Qwen3.5 系列 hybrid attention/GDN；不能据此宣布其他模型已支持。
- 固定 vLLM 0.30.0 V2 runner、torch 2.13.0+cu130、transformers 5.17.0，
  GGUF 插件固定修订；单卡 RTX PRO 6000 Blackwell、TP=1、eager、同步调度、纯文本。
- 原生 prefix caching 关闭；跨轮复用使用插件自己的 exact-prefix 会话 checkpoint。
  当前草稿逻辑位置上限 262144，尚不能支持无限增长的逻辑历史。
- BF16 用于激活和草稿，**没有新增 BF16 目标权重主线**。其他目标量化、KV 量化、
  多 GPU、CUDA graph、异步调度、多模态和 LoRA 不在已验收支持范围。

## 吞吐与任务结果

| 场景 | 观测结果 | 能说明什么 |
| --- | --- | --- |
| 短历史 warm C4 | 88.203 → **173.112 合计 tok/s，1.963×** | Q8 Tensor Core 有明显批量收益；输出不同、自动页池容量略有不同，尚非最终同条件质量/性能验收 |
| 四条约 132–134K 历史 C4 | 输出到达窗口合计 **10.443 → 18.619 tok/s**；服务时间 1862.795 → 761.158 秒 | prefill/刷新阻塞下有改善，仍远低于短请求；不是稳定 decode 峰值，也不是反复复测的最终结论 |
| 134K 会话复用 | populate 183.708 秒 → reuse **5.172 秒**；TTFT 182.686 → 4.230 秒 | 大部分收益是避免重复 prefill；对应 decode 68.328 → 73.852 tok/s，仅 63 个 token 间隔 |
| 实际 C2 稳定片段 | 106 秒筛选区间，accepted-authority 提交速率合计约 **85.94 tok/s** | 只读诊断采样，排除 prefill/刷新，存在快照滞后；不是 SSE/端到端验收吞吐 |

性能证据分别为 `engine_short_warm_native_q8_01`、
`engine_short_warm_tensorcore_q8_dynamic_01`、
`engine_long_c4_dflash_direct_cadence_02`、`engine_long_c4_dflash_tensorcore_01`、
`session_http_long_01`、`agent_sessions_c2_initial_01/decode_progress_01`。
历史对照并非全部同一提交，开发/host 测试与部分运行重叠；必须补独立、同条件复测。

**真实任务尚未通过验收：**

- 非会话 C2（termenv/tomlkit，`agent_tensorcore_c2_initial_03`）均到达官方
  90 分钟上限、reward **0**。已完成请求加权 decode 为 **27.07 / 20.07 tok/s**。
  这是失败的两任务结果，不是完整任务集结果。
- 会话 C2（`agent_sessions_c2_initial_01`）的后端在 **08:21:01** 记录发送 SIGTERM，
  随后退出，manager 将状态标为 failed；发起终止的来源尚未确认。
  08:23 左右停止仍依赖失效后端的测试进程，保留中断证据；**没有有效最终质量分数**。
  最终 harness 状态为 `interrupted`，两个 Pier 进程均退出 130、`unscored`；
  后端终止后每个任务还记录了 24 次 HTTP 错误，不能只报告成功调用。
- 中断前保存的已完成调用：termenv **33 次、36.36 tok/s、最大 prompt 83997**；
  tomlkit **28 次、27.28 tok/s、最大 prompt 109075**。这是按请求 decode 时间加权的
  局部观测，不能相加成 C2 吞吐，不能与完整任务的结果作等工作量比较。
- 会话复用实际命中计数从任务前基线 18 增至末次快照 79；证明发生复用，
  不证明任务成功、压缩后的长期质量或完整结束后的资源清理。

早期失败也已保留：缺工具 parser、代理 900 秒超时、启动 capture 未正确 arming、
会话 warmup 元数据缺失、64-token C4 未观测到四个同时活跃 authority。
这些失败不计为通过；对应修复及后续限定范围的通过结果见历史验收日志。

## 尚未实现完整的能力

1. 全进程 host RAM 字节准入、跨请求公平 I/O、CPU/NVMe/GPU 联合资源管理。
   当前 checkpoint、read cache、staging 等各自有界，不能声称总内存已严格有界。
2. 超过 262144 的持续逻辑位置适配；跨 worker/重启恢复、checkpoint TTL/expiry。
3. 更多模型状态、位置和 KV 格式适配器及其验证；目前仅提供分层接口和已测主线路径。
4. 消除长 prefill/刷新对其他 decode 请求的严重干扰；进一步降低验证成本。
5. CUDA graph、异步调度、多 GPU 等性能/部署模式；现有同步 eager 模式不是最终并发性能上限。

## 尚未做完的测试与下一步

1. **新 public profile、首次请求自动 arming、HTTP middleware 的实际模型 GPU 验收**。
2. **decode 中真实压缩刷新、刷新期间断连取消、C4 survivor/recovery**。
3. **GPU 页池超容量准入**及真实背压；不是只检查 CPU allocator 模拟。
4. **存档 GC 实际回收、硬 NVMe 预留/配额、共享 I/O 字节背压**的原生 GPU 测试。
   已准备 245760-token 合成压力样本和命令，K/G 不变；该样本禁止进入吞吐统计。
5. 更长、增长中的多轮压缩会话，以及并发恢复与 GC 的组合压力/质量检查。
6. 重跑中断的会话 agent 对照、完整十任务集、同精度原生 vLLM/Q8 控制、任务正确率与超时统计。
7. 同输入/停止规则/页池/代码版本的独立 warm C1/C2/C4 重复测试，记录
   合计 decode、TTFT、ITL/最长停顿、prefill、接受率、显存/host/存储峰值。
8. 最终提交完整 GPU 回归及从干净环境复现安装；目前 GitHub 提交仅为开发快照，
   不发布 PyPI 包或宣称 production-ready。

主线精度与 K/G 不变；不以 130 tok/s 或 48 GB 为硬门槛。
是否完成由功能、状态正确性、任务质量及有证据的并发收益共同决定。
